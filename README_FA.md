# نسخه وب React + FastAPI — شروع سریع ویندوز

۱. Python 3.11 به همراه Python Launcher را از python.org نصب کنید.
۲. ZIP را کامل Extract کنید؛ فایل BAT را از داخل ZIP اجرا نکنید.
۳. داخل پوشه mositto-web روی **START_WINDOWS.bat** دوبار کلیک کنید.
۴. در اولین اجرا، محیط مجازی و وابستگی‌ها خودکار نصب می‌شوند. نصب اولیه حجیم است و اینترنت لازم دارد.
۵. مرورگر پس از آماده‌شدن سرور خودکار باز می‌شود. برای دوربین، روی Allow / اجازه‌دادن بزنید.

پنجره ترمینال را باز نگه دارید؛ Ctrl+C برنامه و سرور را متوقف می‌کند. بستن تب مرورگر سرور را خاموش نمی‌کند.
پورت آزاد خودکار انتخاب می‌شود؛ آدرس دقیق در ترمینال چاپ می‌شود. این آدرس در هر اجرا ممکن است عوض شود.
اگر نصب اول خطا داد، پیام در پنجره می‌ماند. بعد از رفع خطا، START_WINDOWS.bat را دوباره بزنید. INSTALL_WINDOWS.bat نیز فقط نصب را انجام می‌دهد و پنجره را برای دیدن نتیجه باز نگه می‌دارد.
برای اجرای روزمره Node.js لازم نیست؛ خروجی ساخته‌شده React در frontend/dist موجود است. وجود Python همچنان لازم است؛ این بسته exe مستقل نیست.

## استفاده از سایت

- «افراد»: نام، شناسه یکتا و نقش را مشخص کنید. دوربین را روشن و «گرفتن عکس» را بزنید یا فایل انتخاب کنید. پیش‌نمایش را ببینید و «ثبت فرد جدید» را بزنید.
- «جلسه جدید»: عنوان و اعضا (معلم و دانش‌آموزان) را انتخاب و جلسه بسازید.
- «حضور و غیاب»: جلسه را انتخاب کنید، عکس تکی/گروهی بگیرید و «بررسی تصویر و ثبت حضور» را بزنید.
- دوربین هنگام گرفتن عکس روشن می‌ماند؛ می‌توانید عکس را دوباره بگیرید. با تغییر بخش یا «خاموش‌کردن دوربین» متوقف می‌شود. ویدیو به‌طور زنده ارسال نمی‌شود؛ فقط عکس انتخاب‌شده پس از زدن ثبت ارسال می‌شود.
- نتایج هر چهره و فهرست حضور نمایش داده می‌شود. در پایان «پایان جلسه» را با تأیید بزنید و CSV بگیرید.
- وبکم را روی همان دستگاهی که سرور اجرا شده، از آدرس localhost یا 127.0.0.1 استفاده کنید. اتصال موبایل به IP شبکه در این بسته تنظیم نشده و دسترسی دوربین روی HTTP شبکه قابل اتکا نیست.
- هنگام خطای مجوز، مجوز Camera را از تنظیمات سایت در مرورگر فعال کنید. اگر دستگاه اشغال است، برنامه‌های دیگرِ استفاده‌کننده از وبکم را ببندید.

## انتقال اطلاعات نسخه قبلی

اگر قبلاً داده ثبت کرده‌اید، هر دو سرور را متوقف و پوشه data نسخه قبلی را به کنار launcher.py در mositto-web کپی کنید. روی data موجود بازنویسی نکنید مگر آگاهانه و با بکاپ. مدل و ساختار دیتابیس همان نسخه قبلی است.

## توسعه React (اختیاری)

به Node.js 22 نیاز دارید. برای تغییر فرانت:

```bash
cd frontend
npm ci
npm run test
npm run build
```

سپس سرور را دوباره اجرا کنید. برای توسعه زنده، API را جدا روی 8000 و `npm run dev` را در frontend اجرا کنید؛ Vite مسیرهای API را به 8000 می‌فرستد.
برای اجرای Linux می‌توانید پس از نصب requirements، از `python launcher.py` در محیط مجازی استفاده کنید.

## اعتبارسنجی این نسخه

۸ تست Python برای API و راه‌انداز و ۴ تست React برای رفتار دوربین موفق بودند؛ خروجی React نیز با موفقیت ساخته شده است. اجرای BAT روی ویندوز، وبکم واقعی و مدل‌های سنگین AI در این محیط تست نشده‌اند؛ پس از نصب، با چند عکس واقعی بررسی کنید.

# Mositto — حضور و غیاب با FastAPI

نسخه مستقل از Tkinter با همان سناریوی ثبت دانشجو/معلم و شناسایی چهره.
مدل YOLO فایل ارسالی در models/model.pt قرار دارد. رابط فارسی React همراه با وبکم، پیش‌نمایش عکس و آپلود فایل به این نسخه اضافه شده است. Swagger همچنان در /docs وجود دارد.

## نصب و اجرا

پیشنهاد محیط: Python 3.11، محیط مجازی جدا. این وابستگی‌های هوش مصنوعی را در محیط پروژه‌های دیگر نصب نکنید.
فایل ZIP را استخراج و ترمینال را در پوشه mositto-fastapi، کنار requirements.txt باز کنید.

### ویندوز PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### Ubuntu / Linux با Python 3.11 نصب‌شده

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

در مرورگر باز کنید: http://127.0.0.1:8000/docs
توقف: Ctrl+C. اگر پورت درگیر است، از --port 8090 استفاده کنید و آدرس مرورگر را هم تغییر دهید.
اجرای CPU کافی است؛ تنظیم CUDA الزامی نیست. نصب کامل TensorFlow/PyTorch حجیم است.
نسخه‌های requirements بازه دارند؛ فایل lock حاصل نصب روی سیستم کاربر نیستند. ترکیب کامل AI در محیط تحویل اجرا نشده است.

## استفاده قدم‌به‌قدم در Swagger

در هر قسمت روی Try it out بزنید، ورودی‌ها را وارد و Execute کنید.

### ۱. ثبت افراد — POST /people

- code: شناسه یکتا مثل S1001 یا T1001؛ بین هر دو گروه مشترکاً یکتا است.
- name: نام کامل، فارسی هم مجاز است.
- role: student برای دانشجو/دانش‌آموز یا teacher برای معلم.
- photo: عکس روشن و روبه‌رو با دقیقاً یک چهره، JPEG/PNG/WebP حداکثر ۱۰ MiB و ۲۰ مگاپیکسل.
- پاسخ 201 حاوی id فرد است؛ برای جلسه کپی کنید.
- عکس گروهی برای ثبت شخص قبول نمی‌شود. چهره بسیار مشابه فرد موجود با 409 رد می‌شود.

GET /people لیست افراد و شناسه‌ها را نشان می‌دهد؛ role فیلتر اختیاری است.
تصویر اصلی نگهداری نمی‌شود؛ بردار چهره در SQLite ذخیره می‌شود. پوشه‌های students و teachers نسخه قدیمی خودکار وارد نمی‌شوند؛ عکس‌های همان پوشه‌ها را از این API ثبت کنید.

### ۲. ساخت جلسه — POST /sessions

برای هر کلاس/نوبت، جلسه جدا بسازید. اعضا شامل معلم و دانشجویان همان جلسه هستند:

```json
{
  "title": "کلاس هوش مصنوعی — جلسه اول",
  "person_ids": ["شناسه دانشجو از مرحله قبل", "شناسه معلم از مرحله قبل"]
}
```

پاسخ، id جلسه می‌دهد. تا قبل از پایان جلسه، کسی که دیده نشده pending است.
فهرست جلسه هنگام ایجاد مشخص می‌شود؛ ثبت افراد جدید آن را تغییر نمی‌دهد.
GET /sessions برای مشاهده جلسات است.

### ۳. حضور و غیاب — POST /sessions/{session_id}/recognize

session_id را وارد و عکس تکی یا گروهی بارگذاری کنید. این کار را برای عکس افراد دیگر تکرار کنید.
تصویر با دوربین گوشی/وبکم خودتان تهیه و سپس فایل را انتخاب کنید؛ سرور دوربین را با VideoCapture باز نمی‌کند.
برای اتصال فرانت‌اند، هر فریم منتخب را با FormData با کلید photo بفرستید.

نتیجه برای هر چهره:

| status | معنی |
|---|---|
| present | حضور جدید ثبت شد |
| already_present | قبلاً ثبت شده، رکورد تکراری ایجاد نمی‌شود |
| unknown | چهره با هیچ فردی مطابقت قابل قبول ندارد |
| ambiguous | دو فرد بیش از حد نزدیک‌اند؛ حضور خودکار ثبت نشد |
| not_in_roster | فرد شناخته شده ولی عضو این جلسه نیست |

box مختصات چهره در تصویر اصلاح‌شده بر اساس EXIF است. distance فاصله کسینوسی است؛ احتمال یا درصد اطمینان نیست.
اگر چهره‌ای پیدا نشود پاسخ 422 است. حداکثر ۳۰ چهره در هر درخواست پذیرفته می‌شود.

### ۴. گزارش و پایان جلسه

- GET /sessions/{session_id}/report: گزارش اعضا و تعداد حاضر، غایب و در انتظار.
- POST /sessions/{session_id}/close: پایان جلسه؛ pendingها از این لحظه absent گزارش می‌شوند.
- بعد از بسته‌شدن، ثبت حضور جدید ممنوع است؛ جلسه را وقتی تمام عکس‌ها ثبت شدند ببندید.
- GET /sessions/{session_id}/export.csv: دانلود گزارش سازگار با فارسی در Excel.
- زمان‌ها UTC و دارای timezone ذخیره می‌شوند.

## ذخیره‌سازی و تنظیمات

دیتابیس به‌طور پیش‌فرض در data/attendance.sqlite3 کنار پروژه ایجاد می‌شود و پس از راه‌اندازی مجدد باقی می‌ماند.
برای بکاپ، سرور را متوقف و کل پوشه data را کپی کنید. تغییر مکان پروژه همراه با data اطلاعات را حفظ می‌کند.

متغیرهای محیطی اختیاری (فایل .env خودکار خوانده نمی‌شود):

| متغیر | پیش‌فرض |
|---|---|
| DATA_DIR | پوشه data پروژه |
| MODEL_PATH | models/model.pt با مسیر مطلق مبتنی بر محل پروژه |
| FACE_THRESHOLD | 0.30 |
| FACE_MARGIN | 0.05 |

برای نمونه PowerShell: `$env:FACE_THRESHOLD="0.30"`
برای Linux: `export FACE_THRESHOLD=0.30`
آستانه کوچک‌تر پذیرش سخت‌گیرانه‌تر است. مقادیر فعلی نقطه شروع آزمایشی هستند؛ با عکس افراد واقعی پروژه، نورهای مختلف و افراد ناشناس ارزیابی شوند.
تغییر مدل embedding نیاز به ثبت دوباره تمام چهره‌ها دارد.

## ساختار و تفاوت با برنامه قدیمی

- app/main.py: FastAPI، اعتبارسنجی، SQLite، جلسات و گزارش.
- app/vision.py: YOLO برای ناحیه چهره و DeepFace/Facenet512 برای embedding.
- models/model.pt: همان وزن ارسالی؛ وزن تشخیص چهره است، نه وزن شناسایی هویت.
- tests/test_api.py: تست گردش کار با موتور چهره شبیه‌سازی‌شده.
- هنگام ثبت، embedding یک بار محاسبه و ذخیره می‌شود؛ برای هر درخواست عکس‌های قدیمی دوباره پردازش نمی‌شوند.
- هر درخواست AI در یک پردازش با قفل اجرا می‌شود. اجرای تک worker برای این نسخه در نظر گرفته شده است.

## دانلود وزن‌های DeepFace و خطاها

در اولین پردازش عکس، DeepFace ممکن است وزن Facenet512 را از اینترنت دریافت کند؛ اولین درخواست طولانی‌تر است. فایل model.pt به‌تنهایی برای حالت آفلاین کافی نیست.
اگر اینترنت سیستم محدود باشد، وزن‌های موردنیاز DeepFace باید پیشاپیش روی همان محیط آماده شوند؛ کش معمولاً زیر ~/.deepface/weights است.
503 یعنی موتور AI خطا داده؛ جزئیات در ترمینال سرور ثبت می‌شود. مسیر مدل، دانلود وزن‌ها و نصب سازگار TensorFlow و tf-keras را بررسی کنید.
409 برای کد/چهره مشابه یا جلسه بسته؛ 422 برای داده یا تصویر نامعتبر؛ 404 برای شناسه ناموجود.

## تست

```bash
python -m pip install -r requirements-test.txt
python -m pytest -q
```

تست‌های Python منطق API را با موتور چهره شبیه‌سازی‌شده بررسی می‌کنند؛ تست‌های React رفتار دوربین را با API مرورگر شبیه‌سازی می‌کنند. دقت تشخیص و وبکم واقعی روی ویندوز در محیط تحویل تست نشده است.

## محدوده نسخه

این نسخه برای اجرای محلی و پروژه دانشگاهی است. ورود مدیر، احراز هویت، اصلاح دستی حضور، حذف/ویرایش افراد و تشخیص زنده‌بودن چهره ندارد؛ عکس چاپ‌شده یا نمایشگر ممکن است پذیرفته شود.
به اینترنت عمومی منتشر نکنید؛ قبل از استفاده سازمانی، احراز هویت، مجوزها و چرخه نگهداری داده لازم است. بردار چهره نیز داده حساس است.
عدم تطبیق همیشه به معنی غیبت واقعی نیست؛ گزارش خودکار باید امکان بازبینی انسانی داشته باشد.
